Written for: whoever deploys the allowlist sheet (you or an ops teammate).

# Allowlist sheet — deploy guide

`Code.gs` is a Google Apps Script web app that stores allowlist submissions in a
spreadsheet. Set it up once, paste the URL into the site's environment, done.

Without it the site writes to `data/allowlist.json`, which is fine locally but
**loses every submission in production** — serverless filesystems are read-only
and reset on each deploy. Deploy this before you open the list.

## 1. Make the spreadsheet

1. Go to <https://sheets.new> and name it something like `BUNII Allowlist`.
2. Leave it empty. The script creates the `Allowlist` tab and its headers on the
   first submission.

## 2. Add the script

1. In the spreadsheet: **Extensions → Apps Script**.
2. Delete the placeholder `myFunction` stub in `Code.gs`.
3. Paste the whole contents of [Code.gs](Code.gs).
4. Save (⌘S / Ctrl+S).

## 3. Deploy it

1. **Deploy → New deployment**.
2. Click the gear next to "Select type" and choose **Web app**.
3. Set:
   - **Description**: anything, e.g. `allowlist v1`
   - **Execute as**: **Me**
   - **Who has access**: **Anyone**
4. **Deploy**, then **Authorize access** and allow the permissions. Google will
   warn that the app is unverified — that is expected for your own script.
   Choose **Advanced → Go to (project name)**.
5. Copy the **Web app URL**. It looks like:

   ```
   https://script.google.com/macros/s/AKfy.../exec
   ```

> **"Who has access: Anyone" sounds alarming — it isn't a mistake.** The site
> calls this URL from its server, with no Google credentials, so the endpoint has
> to be reachable anonymously. The URL is unguessable, it only ever appends rows,
> and it never returns the list — a `GET` gives back nothing but a count. If you
> want a second lock, see [Optional: shared secret](#optional-shared-secret).

## 4. Point the site at it

Set the environment variable wherever the site runs:

```
GOOGLE_SHEETS_WEBAPP_URL=https://script.google.com/macros/s/AKfy.../exec
```

On Vercel: **Project → Settings → Environment Variables**, add it for
Production (and Preview if you want previews writing to the same sheet), then
redeploy — env changes don't apply to existing deployments.

## 5. Check it works

From the Apps Script editor, run `selfTest` (pick it in the function dropdown,
press **Run**) and open **Execution log**. It submits a test entry, submits it
again to prove the duplicate check fires, and checks the count moved by exactly
one. The last line is the verdict:

```
count before      : 0
submit            : {"position":1}
submit again      : {"error":"duplicate"}
count after       : 1
PASS — wiring is good. Delete the @test row before going live.
```

On `FAIL`, the lines above it say which step went wrong. On `PASS`, delete the
`@test` row from the sheet.

Once the site is deployed, the join form's "N already in" counter reads from
this endpoint — if it shows a number, the wiring is good.

## Re-deploying after an edit

Apps Script keeps serving the old code until you say otherwise, and **a new
deployment gets a new URL**. To keep the existing URL:

**Deploy → Manage deployments → (pencil icon) → Version: New version → Deploy**

Use that every time you change `Code.gs`. If you use "New deployment" instead,
you must update `GOOGLE_SHEETS_WEBAPP_URL` to match.

## What lands in the sheet

| Column | Value |
| --- | --- |
| Joined At | ISO timestamp, written by the script |
| Handle | `@handle`, taken from the verified X session |
| Wallet | EVM address, validated as `0x` + 40 hex before it gets here |
| Invite Code | `BUNII-XXXXXX`, generated by the site |
| X User ID | Numeric X id — the stable identity behind the handle |
| Quote Link | The post that cleared the quote quest |

Keep the **X User ID** column. Handles can be changed or sold; the id can't, so
it is what an audit of the list actually rests on.

## Duplicates

The script refuses a wallet already on the list (`duplicate`) and an X account
already on the list (`duplicate_x`); the site turns both into a readable message
and a 409. Wallet matching ignores case, since addresses get pasted in mixed
checksum casing.

Submissions are serialised with a script lock, so two people joining at the same
instant can't both take the same position or slip a duplicate past the check.

## Optional: shared secret

To stop anyone who finds the URL from appending rows:

1. In `Code.gs`, set `SHARED_SECRET` to a long random string and re-deploy (see
   above — new *version*, same URL).
2. Set the same value as `ALLOWLIST_WEBHOOK_SECRET` in the site's environment.
3. In [`src/lib/allowlist-store.ts`](../../src/lib/allowlist-store.ts), add it to
   the POST body in `submitToSheet`:

   ```ts
   body: JSON.stringify({
     ...sub,
     inviteCode,
     secret: process.env.ALLOWLIST_WEBHOOK_SECRET,
   }),
   ```

Step 3 is a code change, so it isn't wired up by default — skip the whole
section unless you want it.

## Exporting for the mint

The wallet column is what you'll snapshot. **File → Download → CSV**, or select
column C and copy. Drop the header row and dedupe before building a merkle tree
or uploading an allowlist to a contract.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| Counter stuck at 0, submissions fail | `GOOGLE_SHEETS_WEBAPP_URL` unset, or set but not redeployed |
| `Sheets webhook returned 401/403` | Access isn't "Anyone", or the deployment was never authorised |
| Edits to `Code.gs` have no effect | You saved but didn't deploy a new *version* |
| `Busy, try again.` | Lock contention under load; the site surfaces it as retryable |
| Rows appear but the site 502s | An error string the site doesn't recognise — check **Executions** in the Apps Script editor |
